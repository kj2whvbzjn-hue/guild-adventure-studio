# AIチップUI 手動実機受入 — GA-B486.193 / GKS-B615

## 目的

実端末上で、Formal AIチップUIの起動、8×8盤面、2方向分岐、Validator、保存・再読込、自作Preset、戦闘接続を確認する。

## 開始URL

Game公開URLの末尾へ `?deviceTest=1` を付ける。

例: `.../game/?deviceTest=1`

開発者パネル内の「実機受入テスト」で、最初に「自動診断を実行」を押す。自動診断のFAILが1件でもある場合は手動判定を進めず、結果JSONを保存する。

## 前提

- Game Build表示が `GA-B486.193`、Studio Build表示が `GKS-B615` である。
- Formal AI Master取得がPASSし、AI Masterが1件以上存在する。
- 現行正式データでは公式AI Presetは0件でもよい。公式Presetは今回の受入対象外とし、自作Presetを確認する。
- 実機ブラウザのlocalStorageが利用できる。

## 最小の有効AIを作る

1. 「はじめから」でGameを開始する。
2. 拠点 → 訓練所 → 冒険者を選ぶ → 任意の冒険者 → 「AIチップ編集」を開く。
3. 8×8の盤面が表示され、状態表示が「正式AI Masterを読込中…」から更新されることを確認する。
4. 次の4チップを配置する。座標は左上を1列1行として数える。
   - 2列2行: CONDITION「常に成立」
   - 3列2行: TARGET「HPが最も低い敵」
   - 4列2行: ACTION「通常攻撃」
   - 2列3行: ACTION「待機」
5. 2列3行の「待機」をタップし、90°回転する。CONDITIONのFALSE出力と待機ACTIONの入力が向き合う。
6. TRUE側が `常に成立 → HPが最も低い敵 → 通常攻撃`、FALSE側が `常に成立 → 待機` と自動接続されることを確認する。
7. 盤面状態がVALIDになり、「保存」が有効になることを確認する。

## Validator確認

- ACTIONを一時的にずらす、または回転させて接続を壊し、盤面がERRORになり保存不可になることを確認する。
- Undoで戻し、VALIDへ復帰して保存可能になることを確認する。
- 問題ジャンプがERROR位置へ移動することを確認する。

## 保存・再読込

1. 「保存」を押し、「保存済み」表示になることを確認する。
2. AI編集を閉じ、同じ冒険者で再度AI編集を開く。
3. 4チップと配置・回転が維持されていることを確認する。
4. Gameページを再読込する。
5. 同じ冒険者で再度AI編集を開き、同じProgram/Layoutが復元されることを確認する。

## 自作Preset

1. VALIDな状態で「プリセット」を開き、自作Presetを作成する。
2. 読込、複製、名前変更、削除を順に実施する。
3. 読込後に盤面へ反映されること、Undoで読込前へ戻れることを確認する。

## 戦闘接続

1. AIを保存した冒険者を遠征パーティへ入れる。
2. 戦闘を開始する。
3. Formal AIがACTIONを決定し、通常攻撃または待機が予約・実行され、戦闘が停止せず進行することを確認する。
4. 戦闘結果から拠点へ戻り、保存済みAIが維持されていることを確認する。

## PWA / 再起動

- Safari/Chromeの再読込後もBuildが変わらないことを確認する。
- PWAインストール済みの場合はアプリを終了して再起動し、同じBuildと保存済みAIが維持されることを確認する。

## 結果提出

実機受入パネルで各項目をPASS/FAILへ設定し、「結果JSONをコピー」または「結果JSONを保存」を使用する。FAIL時は端末名、OS、ブラウザ版、再現手順を端末メモへ記載する。
