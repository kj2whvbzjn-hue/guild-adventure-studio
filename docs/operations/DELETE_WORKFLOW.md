# 削除例外ワークフロー

削除は例外操作である。通常更新では`DELETE_MANIFEST.txt`を空（コメントのみ）にする。

## 1. 基準を固定する

1. GitHubの最新コミットを確認する。
2. `Code → Download ZIP`で取得したソースを調査基準にする。
3. Pagesの反映は待たなくてよい。

## 2. 削除しない代替案を確認する

- 分割
- 移動
- 参照切替
- 生成防止
- 索引からの除外
- 非推奨化

代替案で解決できる場合は削除しない。

## 3. 影響を調査する

削除候補ごとに以下を確認する。

- HTML、JavaScript、PHP、Python、JSONからの参照
- マニフェスト、スキーマ、テスト、fixtureからの参照
- 動的に組み立てられるパス
- 生成元・生成先の関係
- 代替先
- 復旧方法

## 4. 人間の個別承認を作る

`DELETE_APPROVAL.json`に、対象ごとに次を記録する。

- 完全一致パス
- 許可カテゴリ
- 削除が必要な理由
- 削除しない代替案を採用できない理由
- 影響範囲
- 復旧方法

一般指示は承認として扱わない。

## 5. 今回分だけをマニフェストへ記載する

`DELETE_MANIFEST.txt`には、今回実際に削除するパスだけを1行1件で書く。
過去に削除済みのパスを再掲しない。

## 6. 機械検査

```bash
python3 tools/inspection/run.py full --context update --fail-fast
```

必須条件:

- `DELETE_MANIFEST_OK`
- `BLOCKED 0`
- 削除件数と確認画面の列挙件数が一致
- 保護領域を含まない
- 承認ファイルの対象と完全一致

## 7. 配置

1. Studioで実削除一覧を確認する。
2. 人間が削除許可を有効化する。
3. 確認画面でパスを再確認する。
4. 単一Commitで配置する。

削除機構を変更した場合は、まず機構だけを配置し、ページ更新後の別更新で削除する。

## 8. 完了確認

同じ更新ZIPで再確認し、次を満たすこと。

```text
ADD 0 / MODIFY 0 / DELETE 0 / BLOCKED 0
```

大きな削除や構造変更後は、GitHubから最新ZIPを取得し、次の正式基準にする。
